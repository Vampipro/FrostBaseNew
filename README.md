# FROSTBASE v2 — чекер скамерів (Next.js + Prisma + Neon)

Node.js 22+ (підходить 26 LTS).

## Локальний запуск
1. `npm install`
2. Скопіюй `.env.example` → `.env`, заповни:
   - `DATABASE_URL`, `DIRECT_URL` — НОВА база Neon (pooled і direct рядки)
   - `OLD_DATABASE_URL` — стара база (лише для міграції, тільки читається)
   - `SESSION_SECRET` — довгий випадковий рядок
3. `npx prisma db push`      — створити таблиці
4. `npm run db:seed`          — типи (людина/бот/NFT), базові теги, інструкція
5. `npm run migrate:old`      — перенести стару базу (повторно з очищенням: `-- --wipe`), дивись `migration-report.json`
6. `npm run make-admin -- твій_логін`   (або `-- логін пароль`, щоб створити нового)
7. `npm run dev` → http://localhost:3000

Адмін-панель: `/admin` (ролі: admin — усе, moderator — модерація, коментарі, апеляції, бани).
Додати ще адмінів: вкладка «Користувачі» в адмінці.

## Деплой (Vercel + Neon)
1. Залий проєкт у GitHub, імпортуй у Vercel.
2. Змінні оточення: `DATABASE_URL` (pooled), `DIRECT_URL`, `SESSION_SECRET`.
3. Таблиці та міграцію виконай локально (кроки 3–6) проти нової Neon-бази — до чи після деплою.

## Захист від спаму
- Ліміт заявок з одного IP (за замовчуванням 3 за 24 год, змінюється в адмінці)
- Honeypot-поле у формах, перевірка дублів, ліміти на голоси/коментарі/апеляції/реєстрацію/вхід
- Бан IP з адмінки; ліміти рахуються в таблиці `RateLimit` (без Redis)

## Усі ключі та паролі — тільки у Vercel (не в коді і не на GitHub)
У коді немає жодних секретів. `.env` у `.gitignore`, тому на GitHub він не потрапляє.
Рядки баз і `SESSION_SECRET` задаються лише у Vercel: Project → Settings → Environment Variables.
Без `SESSION_SECRET` у продакшені сайт навмисно не запуститься.

## Деплой без GitHub (код теж лише у Vercel)
1. `npm i -g vercel`
2. `vercel login`
3. У папці проєкту: `vercel` (створить проєкт; на питання відповідай Enter)
4. Додай змінні: `vercel env add DATABASE_URL production`, те саме для `DIRECT_URL` і `SESSION_SECRET`
5. `vercel --prod`
Кожне оновлення: `vercel --prod`. Автодеплою при зміні коду в такому режимі немає.

## Налаштування вигляду
Іконка ⚙ у шапці: тема (Frost / Neon / Світла), перемикачі фону, сітки, скан-ліній, анімацій і свічення, кнопка «Lite-режим» (вимикає всі ефекти) і «Скинути». Налаштування зберігаються в браузері. Мова за замовчуванням — російська.

## Оновлення схеми та швидкість
Після оновлення проєкту один раз виконай `npx prisma db push` — додаються індекси для швидкого сортування.
Для швидкого пошуку на великій базі (необов'язково) у Neon → SQL Editor виконай:
```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX IF NOT EXISTS scammer_name_trgm ON "Scammer" USING gin (lower(name) gin_trgm_ops);
```

## Захист (що вже є)
- CSRF: запити, що змінюють дані, приймаються лише з вашого домену (`middleware.ts`)
- Заголовки безпеки: CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy
- Ліміти по IP без гонок (заявки, голоси, коментарі, апеляції, реєстрація, вхід, окремо по логіну), бани IP, honeypot
- Посилання з бази виводяться лише якщо вони http(s); паролі — bcrypt; вхід не видає, чи існує логін
- Кеш статистики/налаштувань на 15–60 с, пошук і перегляди без зайвих записів у БД


## Оновлення схеми (описи кількома мовами + перевірка ботів)

У `Scammer` додано поля `descriptionI18n`, `botCheck`, `botReward`, `botSponsors`, `botUsage` (усі з дефолтами, дані не зачіпаються).
**Перед деплоєм** виконай один раз проти Neon: `npx prisma db push` — інакше Prisma-клієнт не знайде нових колонок.
